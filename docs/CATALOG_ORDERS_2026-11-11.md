# 找店筛选与订单入口完善

## 用户可用的功能

- 找店页可组合选择店名、店铺分类、商圈/地址、人均预算、最低评分及“有优惠券”，并保留评分/价格排序。明确搜索后再翻页，未提交的输入不会混入下一页。
- 筛选条件保存到当前网址，刷新或分享同一网址可恢复；清空筛选恢复默认列表。结果和计数来自后端，不在已加载页面内过滤。
- 订单页提供“全部订单”和“已领取”入口，分别复用原 `/voucher-order/mine` 与 `/voucher-order/mine/vouchers` 查询，支持各自分页和刷新。切换期间旧响应不会覆盖新范围。
- 订单号提供复制按钮，保留Long ID完整位数；剪贴板不可用时提示手动选择复制。
- 订单可展开领取时保存的规则快照，不以当前券的新规则替代订单规则。
- 秒杀请求的SUCCESS提示改为“订单已创建”，不据此宣布付款或领取完成。

## 后端查询与边界

`GET /shop/catalog` 在兼容原有参数的基础上，增加 `area`、`maxPrice`、`minScore` 和 `hasVoucher`。Controller依赖原服务接口，旧五参数服务方法保留并委托给新的DTO查询方法。

- `maxPrice`为人均价格的元，允许0到100000；`minScore`为0到50的数据库评分整数，4.5分传45。
- 店名最多50字，商圈/地址最多50字，页码1到10000，每页最多20家。
- 店名和商圈中的 `%`、`_`、`!` 按字面搜索；LIKE使用绑定参数，不拼接用户SQL。
- “有优惠券”按当前数据库的上架状态、库存及活动时间筛选。它不校验当前用户是否已经领取，也不预留库存；最终资格仍以领取接口为准。
- 分页稳定排序并在前端按ID去重；查询不是快照事务，商品变化时总数及分页仍可能短暂变化。
- “已领取”沿用原服务的状态2查询，不能当作真实收款凭证。订单查询仍强制当前登录身份。

## 本轮验证

205项后端隔离回归、65项前端测试、Vue模板编译及Checkstyle通过。新增后端测试覆盖组合条件、字面特殊字符、分页及库存变更；库存变更测试清除同事务测试会话的MyBatis缓存，模拟新的HTTP请求，不放宽断言。

浏览器新增9项交互检查通过，覆盖条件组合、网址恢复、清空筛选、订单范围切换、长ID复制、规则快照及取消按钮可见性。截图覆盖1440、390、320px；API及剪贴板均为测试桩，没有修改实际订单或系统剪贴板。

本地实际接口14项只读检查通过，包含有效券店铺复核和未登录订单查询保护。完整汇总见 [catalog-orders-verification.json](catalog-orders-verification.json)。全站页面回归结果也在该汇总中。
