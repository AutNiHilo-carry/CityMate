# Phase 7：单 Agent 只读业务查询

后续已完成 [四类选定真实模型联调与修复](PHASE7_AGENT_LIVE.md)，当前代码及本地包以该记录为准。本页下方的测试与发布数据是初版历史记录。

日期：2026-11-09。本阶段把已有查询工具与轻量 RAG 接到一个有边界的模型工具循环，不改变交易、库存、消息和补偿链路。

## 解决什么问题

原规则问答只检索已发布资料，不能根据自然语言查询当前商户和优惠券。新增登录接口 `POST /agent/query`，模型可以先取得真实分类、商圈，再查询商户、实时优惠券、本人订单、领取进度或公开规则，读取结果后继续选择工具，最后回答或要求补充条件。

例如：“找武林商圈人均 50 元以内的火锅店，看看有哪些优惠券。”分类和商圈来自实际目录，价格与券来自业务工具；使用规则通过知识检索获得，回答附来源和版本。“附近”缺少坐标时应要求补充位置或改用商圈，不允许模型编造坐标。页面目前没有获取定位，用户可在同一次问题中写明商圈。

每次请求独立执行，没有历史会话记忆。用户补充条件时，需要在新问题中带上完整条件。

## 实现边界

| 部分 | 本阶段实现 |
| --- | --- |
| 模型协议 | DeepSeek 原生 Function Calling；工具结果通过匹配的 `tool_call_id` 返回模型；不暴露或保存模型推理内容 |
| 工具 | `listShopTypes`、`listAreas`、`searchShops`、`listShopVouchers`、`listMyOrders`、`getClaimStatus`、`searchKnowledge` |
| 身份 | 用户只从服务端登录上下文取得，并传递到受限工作线程；不接受模型指定查询他人的身份 |
| 范围 | 选定店铺限制优惠券和知识查询；选定券限制知识查询。商户搜索本身仍可按问题搜索其他商户 |
| 输入 | 工具名白名单、唯一调用 ID、JSON 对象参数、参数白名单及原业务工具校验；未知写工具拒绝整批调用 |
| 输出 | 后端业务字段白名单、工具结果大小限制、最终 JSON 格式与引用编号校验；不接受回答中的 HTML 或 HTTP 链接 |
| 来源 | 沿用 BM25 检索；生成后重新核对所有检索证据的来源版本、有效性和券规则摘要，过期时丢弃回答 |
| 预算 | 每请求最多 5 轮模型调用、8 次工具调用；模型单次最多 6 秒，整体预算 25 秒，单工具等待最多 3 秒 |
| 资源 | 每实例最多 2 个 Agent 请求同时运行；工具线程 2 个、队列 4 个；每用户每分钟 3 次、每来源地址每分钟 6 次 |
| 页面 | `/assistant.html` 默认智能查询，保留规则问答；展示回答、来源、完成后的查询步骤和基于实际结果的商户/券卡片 |

协议采用官方 API 中的 `tools`、`tool_choice` 与 Tool 消息格式；参数仍须由服务端校验，模型返回不等于可信调用。[DeepSeek API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)

预算通过网络超时、步骤间检查及任务取消执行，不是所有数据库驱动均可立即中断的硬实时承诺。Nginx 后来源地址可能是代理地址，当前地址限流不是完整的可信代理客户端识别方案。

## 可以和不能宣传的内容

- 可以描述“单 Agent 原生工具调用 + BM25 RAG + 业务只读查询”，不能写成多 Agent、向量检索或自进化系统。
- 这里只提供查询，没有 AI 领券、下单、支付或取消工具。领取受理和履约成功不同，`SUCCESS` 也不表示已付款。
- 查询结果是当时快照，不能承诺下次仍有库存或仍满足领取资格；需要操作时进入原业务页面。
- 格式和引用校验不能证明模型每句解释都正确；尚未完成端到端任务成功率、幻觉率、延迟分位数或 Token 成本评测。
- 页面步骤在请求结束后显示，尚未实现 SSE 实时进度；来源原文保持文本渲染，不使用 `v-html`。
- 该阶段不新增中间件，不升级 Java/Spring Boot，也不引入不兼容的 Spring AI。
