# AI 查询与后续操作优化

日期：2026-11-16。

## 参考与定位

参考[美团“小团”官方介绍](https://www.meituan.com/news/NN260727198008607)中表达需求、推荐方案和用户确认后继续操作的路径，以及[大众点评的商户、点评与优惠组织方式](https://events.dianping.com/m/wap.htm)。本轮据 CityMate 已有接口实现连续的找店、查券和规则确认，不包含订座、真实支付、打车或多 Agent。

## 本轮完成

- **直接说需求**：智能查询不要求先选店；店铺和券范围改为可选展开区。手机缩短重复介绍，常见问题两列显示；320×900 视口初始发送按钮位于底部导航上方。
- **补充条件继续查**：回答后可补充商圈、预算等条件。前端把原问题与补充文本组成新的完整请求，沿用原店铺、优惠券与查询模式；不假装服务器记住整段聊天。总长度仍限制为 200 字，超长原问题进入保留原范围的显式编辑模式，不静默截断。
- **从推荐继续查券**：店铺卡的“查这家店的券”发送带合法 shopId 的只读 Agent 查询，不下单。商户和优惠券分组，每组先展示 3 条，支持展开。
- **结果更完整**：有店铺和券的混合结果时，为两类结果保留展示位置，整体仍最多 20 条；大量店铺不会挤掉所有优惠券。只有经过数字校验的价格才展示，缺失、布尔或空白价格不能当作免费。
- **回答更易读**：Agent 和规则问答提示词要求先结论、最多 3 个要点及一个下一步，使用日常中文解释内部状态；保留证据、引用、权限、实时业务状态和写操作边界。
- **确认文案更准确**：付费券预览按钮明确为“确认创建待付款订单”；状态提示使用“订单已生成”“结果还在核对”等说法，仍区分受理、完成与付款。
- **等待与恢复**：等待超过 8 秒只说明仍在等回复，不伪造工具进度；查询中禁用重复发送，重试使用原请求。保留来源原文及明确的找店 / 订单入口。
- **修复账号与草稿问题**：领取请求进行中不会吞掉提问草稿；切换账号清除个人问答与草稿，旧回答、旧来源或旧预览不能覆盖新账号状态或提前解锁新请求。
