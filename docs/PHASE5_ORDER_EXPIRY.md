# Phase 5：付费秒杀订单超时关闭与库存释放

验证日期：2026-11-05。本阶段扩展已有单体订单、Outbox 和 Redis 链路，不增加数据库表或中间件。选定本地回归 40 项、真实 RocketMQ 5 项，共 45 项唯一用例通过，0 失败、0 错误、0 跳过。Checkstyle、Java 8 目标编译和打包通过，已核对 JAR 的配置、Mapper、迁移与 Lua。实际测试结果以 [验证汇总](phase5-order-expiry-verification.json) 为准。

## 业务规则

- 新建付费秒杀订单在正式落库时登记截止时间，沿用 `citylens.reliability.order-timeout-minutes`，默认 30 分钟。截止从订单落库计算，不是入口受理时刻。
- 超时只取消 UNPAID；模拟支付在截止时间前成功后，延迟到达的关单不会取消它。免费券仍直接领取，不因时间到期释放库存。
- 取消归还库存，但保留同一活动的一人一单资格。原用户再次请求返回原订单号，需查询其 CANCELLED 状态；其他合格用户可在活动有效期内竞争归还的库存。
- 预约 SUCCESS 仍表示曾完成订单落库，订单自身的 UNPAID、PAID、CANCELLED 表达后续生命周期。不能把 SUCCESS 当作已经收款或当前仍持有券。
- 活动结束后可完成库存归还和对账，但不绕过活动时段重新售卖。
- 本轮支持自动超时取消，未开放用户主动取消秒杀订单。普通券原有手动取消规则不变。

历史秒杀订单若没有 `expire_at`，本轮不自动补期限、批量取消；需先核对再单独迁移。没有新增 Flyway 迁移，复用 V6 的截止时间列和 V7 的 Outbox 幂等键。

## 事务和恢复责任

付费秒杀履约事务现在同时完成：条件扣数据库库存、写订单快照、预约 SUCCESS、订单创建事件、截止时间和延迟关单事件。任一步失败时数据库一起回滚，Redis 入口预占继续由原重试/复核链路负责。

到期消息和数据库扫描都调用统一 `closeExpiredOrder`：锁定订单，复查当前状态与数据库时间，条件迁移为 CANCELLED。秒杀订单在同一事务内增加一次 MySQL 库存，登记唯一 `SECKILL_RELEASE` 任务，以及 ORDER_CLOSED。重复关单不会再次增加库存。

Redis 归还在事务提交后经原 Relay、消费组 `activities` 和 Inbox 执行。新 Lua 使用 `seckill:released:<orderId>` 记录释放结果，库存增加和标记写入在一个脚本中完成；标记不设 TTL。Redis 已执行、数据库确认失败时，重放识别标记，避免再次增加库存。仍保留买家集合与 user→order 映射，不恢复该用户购买资格。

MySQL 库存已经归还、Redis 任务尚未完成期间，两边暂时不同，任务负责收敛。遇到 Redis 缺失、错误类型或归属不符时拒绝盲目增加库存，保留任务重试/复核。

取消和 Redis 释放复用 `lock:publish:<voucherId>` 活动锁，并持有到当前数据库事务结束。恢复活动时暂停入口，检查未完成的库存释放任务，再重新读取数据库库存。这样避免把尚待释放的库存重建后，又被任务再次增加。对应测试是隔离环境中的协调验证，不代表任意分布式锁失效都已实测。

库存对账的 `persisted_orders` 现在表示仍占用库存的非取消订单数，取消订单仍留在订单表。恒等式是初始库存 = 数据库剩余库存 + 非取消订单数；不能把历史订单总数直接代入。

## 验证场景

新增本地集成用例覆盖：

1. 超时取消、DB 与 Redis 各归还一次，重复消息不重复归还，资格不恢复。
2. 免费券不生成支付截止事件，也不被到期任务取消。
3. 截止前模拟支付成功后，迟到关单不释放库存。
4. 已到期时支付与关闭并发，拒绝迟到支付，只登记一次关闭。
5. 截止消息缺失时，数据库扫描兜底。
6. 释放任务插入失败时，取消、数据库回库与关闭事件一起回滚。
7. Redis 脚本拒绝异常库存后，持久任务恢复，数据库不再重复回库。
8. Redis 释放成功、Inbox 插入失败时，依靠无 TTL 标记重放。
9. 未完成的释放任务阻止活动恢复；完成后重建库存不重复增加。
10. 活动结束后归还库存，不允许新用户继续受理。

另保留普通订单、模拟支付、既有秒杀和失败补偿回归。真实 RocketMQ 测试新增“付费秒杀延迟关单→生成释放事件→消费释放事件”链路，并复跑已有 Broker 用例。结果详见汇总，不将不同阶段重复执行的测试累加。

## 边界

支付仍是受配置开关控制的本地模拟，没有接入真实收款、退款或核销。Redis 故障测试使用异常库存内容触发脚本拒绝，数据库故障使用测试触发器；不能宣传成实际断网、杀进程或断电实验。

Redis 释放标记当前长期保留；今后若归档任务或清理活动数据，必须联合设计，不能只按时间删除标记而仍允许旧任务重放。Redis 预占或释放记录丢失时继续保留恢复门禁和人工核对，不承诺无损自动恢复。

没有新增 QPS、P99 或恢复 SLA。本阶段收尾后，下一步是在同一隔离环境下整理交易压测、真实故障演练和数据对账，区分入口受理吞吐与最终履约吞吐。
