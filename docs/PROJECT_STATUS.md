# CityMate 项目进度与对话交接

更新日期：2026-11-02（北京时间）。此文档是项目一的交接入口，描述当前实现，不代表所有计划已完成。

## 项目定位

CityMate｜本地生活智能服务平台。基于黑马点评课程扩展，采用 Java 单体架构，以后端并发、数据一致性和可靠业务处理为重点。AI 是自然语言入口，采用单 Agent 方向，不做微服务，不强加多 Agent。课程来源保留，升级内容作为项目贡献记录。

## 已有后端升级

- 店铺、笔记、关注、签到、普通券、秒杀、订单和配套桌面网页。
- 多层缓存、版本和锁 owner 校验、Canal CDC 与缓存变更同步。
- Redis Stream 异步秒杀、持久预约、Outbox/Inbox、RocketMQ 租约投递、重试与幂等。
- 超时关单、补偿对账、Kafka 行为热榜和隔离测试。具体边界见 Wiki，不能概括成所有链路已生产可用。

## 本轮已完成的 AI 能力

1. 四个内部只读查询工具：商户搜索、商户优惠券、本人订单、领取请求进度。已实现权限、参数和超时边界，尚未接入模型工具循环。
2. 知识来源发布、切分、版本、撤回及生效窗口管理，MySQL 三张知识表，Flyway V10。
3. Java BM25 关键词检索，限定平台 / 店铺 / 优惠券范围；券规则保存摘要并复核，返回来源及版本。
4. DeepSeek 规则问答：检索原文 → 模型生成结构化回答 → 校验引用 → 复查来源。限流、并发限制、超时和无证据兜底已实现。
5. `/assistant.html` 基础聊天页：登录后提问、店铺/券选择、状态提示、来源原文查看和重试。沿用 Vue 2.5.16，无浏览器端 Key。

当前 RAG 为 BM25 + DeepSeek；没有 Embedding、向量库、混合检索或重排序模型。基础问答每次独立检索，不包含历史上下文；页面问答记录仅在内存中保留，刷新后清空。

## 已验证的事实

- DeepSeek 接入阶段：44 项选定后端测试、Checkstyle 和打包通过，不是整个历史测试集总数。
- 一次真实模型联调：6 项 HTTP 检查通过，包含未登录拦截、无证据兜底、模型回答及来源版本查看。单次约 1.5 秒，不能写成平均耗时、P99 或准确率。
- 聊天页面阶段：18 项前端测试通过；用捆绑 Vue 编译模板并检查文本渲染；页面、模块和 CSS 返回 200。
- 浏览器控制通道不可用，聊天页面尚未完成浏览器布局、键盘及截图验收。
- 约 4922 → 9332 QPS、P99 6.583 → 4.151 ms 是 2026-10-11 的历史单实例热点查询记录，不是本轮或全系统容量。

## 下一步顺序

1. 浏览器验收聊天页，修正实际发现的交互和布局问题。
2. 加入 SSE，区分真实的检索、工具执行和回答事件，不伪造执行进度。
3. 接入单 Agent 工具循环：模型选择商户 / 券 / 规则等工具，限制调用次数、总耗时和重复调用。
4. 加入明确的用户确认、领券幂等和履约结果追踪；库存、价格、资格和订单状态必须走实时接口。
5. 整理 40～60 条业务评测问题，做可复现的模型效果与端到端测试，再进行本人新压测。
6. 向量召回是否引入取决于语义召回不足的对照结果，不为凑技术栈增加组件。

目标演示：找附近人均 50 元以内火锅店 → 查真实优惠券 → 检索使用规则 → 展示候选 → 用户确认 → 领取 → 查询履约结果。这条完整链路尚未实现。

## 开发与部署约定

- Java 8、Spring Boot 2.3.12、MySQL、Redis、RocketMQ、Kafka、Canal；不直接引入要求新版 Java 的 Spring AI。
- 本机源代码路径是桌面 `Pr1/hm-dianping`，不要误改聊天应用目录下的其他副本。
- 本机 Docker Compose 项目名 `hm-dianping`。开发配置 `dev/docker-compose.yml`；预构建 JAR 配置 `dev/docker-compose.prebuilt.yml`。
- 模型参数填写本机根目录 `.env`，使用 `scripts/start-citymate-ai.ps1` 更新 Java 容器；`.env` 不上传，参考无密钥的 `.env.example`。
- 开发图片仍依赖项目旁的 `nginx-1.18.0/html/hmdp/imgs`；该外部目录未包含在本仓库。异机部署需按 Wiki / deploy 说明准备资源。
- 真实支付、退款、核销、短信、多机高可用不在已完成范围。秒杀受理不等于履约成功，SUCCESS 不等于已付款。
