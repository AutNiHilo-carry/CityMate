# Phase 7：真实模型只读联调与修复

后续已增加 [用户明确确认的领券与结果追踪入口](CLAIM_CONFIRMATION.md)。本页保留当时真实模型联调的历史结果，模型工具仍然是只读工具。

日期：2026-11-09。当前本地运行包已经包含本页修复。本文是 [单 Agent 初版](PHASE7_READ_ONLY_AGENT.md) 的后续记录，不把模型替身测试当作真实调用。

## 实际发现并处理的问题

1. **平台规则检索的空范围拆箱错误。** `scopedId` 的条件表达式混用了 `long` 和 `Long`，未传店铺或优惠券时会对空值拆箱，工具返回 UNAVAILABLE。将整数分支显式装箱，使未指定范围保持 null；新增无范围工具测试与连接真实隔离 MySQL/Redis 的知识检索、来源复核集成测试。
2. **最终输出不稳定。** 首轮查店、查券已成功，最终回答却被校验拒绝。该次没有保存原始生成文本，不能事后断言具体格式。现对工具轮启用 API 的 `response_format: json_object`，继续校验业务字段和引用；固定诊断码可区分最终结构、引用和不安全文本问题，不返回原始异常或推理内容。[DeepSeek 官方 API](https://api-docs.deepseek.com/api/create-chat-completion/)
3. **把优惠券编号误当成知识引用。** 有券分支曾返回 FINAL_CITATIONS。强化提示，区分知识 citation、券 ID 和列表序号；允许模型根据服务端给出的有效引用集合纠正一次最终 JSON。纠正仍占用原有 5 轮 / 25 秒预算，不删除错误引用后直接放行。再次错误即停止；新增成功纠正、重复错误停止两项测试。

JSON 输出约束仅保证 JSON 形式，不保证字段语义或答案真实性，所以服务端引用、来源版本及业务权限校验继续保留。
