# 助手中的用户确认领券与结果追踪

日期：2026-11-10。本阶段把券查询结果连接到原业务链路，模型工具仍然只有七个只读工具，没有自动领券、支付或取消工具。

## 页面怎么用

1. 在 [助手页](http://127.0.0.1:8080/assistant.html) 查询某店的优惠券。
2. 券结果卡点击“查看并确认领取”，页面调用登录保护的 `GET /assistant/claim-preview`，展示服务端重新读取的券名、金额、规则和可领快照。此步骤不建单。
3. 点击“确认提交领取请求”，页面再核对一次。价格、规则、类型或窗口变化时，更新确认框，要求再次确认；当前不可领时不提交。
4. 普通券提交到原 `/voucher-order/ordinary/{id}`，秒杀券提交到原 `/voucher-order/seckill/{id}`。不提供模型生成的用户身份或任意接口名。
5. 普通券查询本人订单；秒杀查询本人请求进度，最多自动观察十次。PROCESSING 只表示处理中，SUCCESS 只表示订单落库，仍需核对付款状态。付费券只创建待支付订单，本页面不会付款。

## 复用和新增

新增预览 Controller 只依赖 `IQueryToolService`，复用 `listShopVouchers` 的实时金额复核、活动查询、字段白名单和受限执行器。模型文本及其 URL 不作为领取参数；候选 ID 来自后端结构化查询结果，预览再校验券与店铺归属。

交易服务、Lua、数据库迁移和消息消费者没有重写。领取仍使用既有服务端登录身份、一人一单、普通券事务槽位和秒杀原请求映射。前端防双击不能替代这些服务端约束。

已知业务拒绝直接展示拒绝原因；网络超时、无有效回执或服务端错误则显示“结果待确认”。页面不自动重新 POST，改为查询本人订单或跳转订单页；未确认的同一张券不能在当前页面立即再次领取。切换账号时丢弃旧确认框与结果，卸载时停止轮询。

## 必须保留的限制

- **预览不是锁价或库存预约。** 再核对和交易之间仍可能变化；最终金额与规则以创建订单时的业务快照为准。确认框明确提示此点，真实付款不会由本入口触发。若将来需要严格锁价，应在交易事务中增加版本或期望金额校验，不能宣称当前已有。
- 预览只覆盖该店当前工具返回的前 20 张券；找不到时要求重新查询，不能绕过归属校验。
- 暂不跨刷新持久化助手中的提交回执。无回执时按券查询只能确认已落库的本人订单，不能证明还没有异步请求；因此不自动重试，订单页是进一步核对入口。
- 十次自动轮询结束不代表失败；仍可手动查询或进入订单页。
- 不包含真实支付、退款、核销功能；页面识别订单枚举状态不代表实现了这些业务链路。
