## 可复现验证

安装 Maven、JDK 17（编译目标仍为 Java 8）、Node 22 和 Python 3.11 后，在仓库根目录执行：

```text
python scripts/run-ci.py
```

脚本动态发现没有 Spring 上下文注解、没有基类且名称以 Test/Tests 结尾的单元测试，排除 IntegrationTest 和课程 NormalTest。它是明确限定范围的检查，不证明全量测试通过。测试继承、复合上下文注解或新增外部连接需要在评审时调整选择规则；不能用名称检查证明任意新增测试绝无副作用。

运行包括验证脚本自身测试、Maven Checkstyle/编译/后端单元测试、前端脚本语法和前端单元测试。不会读取 `.env`、启动业务服务或调用真实模型。Maven 未加入 PATH 时，可用 `CITYMATE_MAVEN` 指向可执行文件；可选 `CITYMATE_MAVEN_REPO` 指定本机可写的依赖缓存。

每次输出至独立的 `target/verification/<时间-随机ID>/`：

- `manifest.json`：Git HEAD、工作区是否未提交、源文件 SHA256、完整命令、退出码、选中/排除套件及完成时间。
- 全新的 JUnit XML 和命令日志；校验实际套件集合，防止旧报告混入。
- 检查前后源码指纹必须一致；失败尝试保留，不覆盖上一轮。

新增 GitHub Actions 在 push/PR 时执行上述命令，成功或失败均归档为 Actions Artifact，保留 30 天。只有推送并实际运行后才能宣称远端 CI 通过；本地检查不等于 GitHub 已执行。对长期发布版本应另行保留对应 Artifact，避免保留期后链接失效。

集成测试、Broker 故障实验、浏览器和真实模型验证仍按原隔离流程单独执行。`scripts/verify-local.py` 是保留演示数据的人工体验脚本，不进入本 CI。历史缓存压测仍为同 JVM 热点实验，不能作为全系统容量；新的该压测输出移至 `target/benchmarks/cache-benchmark.json`，避免覆盖历史 JSON，其固定阶段顺序和误差统计尚未整改。

## CDC 连续失败保护与恢复

`HMDP_CDC_MAX_CONSECUTIVE_FAILURES` 默认 5。投影、checkpoint 或 ACK 连续失败达到阈值时，当前进程暂停 CDC 消费，保留未确认位点，输出错误日志并置 `hmdp.cdc.blocked=1`。`hmdp.cdc.consecutive.failures` 提供连续失败次数，成功 ACK 后清零。生产监控需对 blocked=1 配置告警；本轮未部署告警服务。

这是停止重复失败并要求人工恢复的策略，不是自动跳过坏数据。缺主键、Redis 故障、数据库不可用都可能触发暂停。暂停时其他业务仍运行，CDC 已不再保证继续同步，应评估缓存陈旧并及时恢复。

恢复顺序：

1. 查看错误日志，检查 Canal、MySQL、Redis 和 binlog ROW 主键/行镜像配置；核验最后一条 checkpoint 及 Canal 实际持久位点。自建 checkpoint 是观测记录，不作为续读游标。
2. 修复原因后重启 Java 消费进程，使其重新连接 Canal 并从未 ACK 位点重放。不要通过手动 ACK 绕过失败，不随意重建 Canal destination。
3. 核验受影响商户/券缓存与数据库一致，再检查成功批次增长、延迟和 blocked 指标；必要时对受影响缓存执行已有失效恢复流程。
4. 若 binlog 已丢失或无法安全重放，需要另行评审全量重建和位点重置，不能用重启承诺恢复全部缺口。

失败次数和暂停状态保存在进程内，重启会清零；未 ACK 位点仍由 Canal 管理。本轮不声称具备持久死信队列或跨进程失败计数。没有测试真实 Canal 断连/毒批的进程级恢复，单元测试只验证阈值、无 ACK、成功清零和 rollback 失败时保留原始原因。
