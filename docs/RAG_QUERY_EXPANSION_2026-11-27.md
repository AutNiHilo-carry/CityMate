# RAG 口语查询：词项扩展与同条件对照

本轮只改查询侧的词项构造，保留 BM25 与原候选权限/版本过滤，不引入向量库、模型查询改写或新业务工具。数据库集成验收仍受 Docker 引擎不可用阻碍；本轮没有启动业务容器、调用真实模型、部署或推送。

## 实现

`KnowledgeQueryTerms` 保留原问句词项，原词权重 1.0，扩展词权重 0.5，原词不会被重复扩展抬权。映射包括付钱/交钱→付款、打烊/关门→营业时间、停哪/泊车→停车、订位/预订→预约。编号只有出现在抢券/秒杀等上下文时才补充订单号；未付款且询问保留时补充超时。否定词和数字保留，移除请问、怎么、什么、需要等通用问法词。

这是有限词表的词法扩展，不是语义理解。它不会改变已有的商户/券范围、用户身份、实时查询或知识版本复查，不能把检索到的段落当成已经证明答案正确。

`KnowledgeRanker.rank` 使用扩展；`rankLiteral` 保留原分词 BM25 基线，只用于相同数据上的对照。原 16 问数据没有修改，另增 12 问补充回归集；两份均为人工构造样本，补充集不是独立人工盲测，也不代表真实用户分布。

## 实际结果

运行：`20261127T140306Z-c7d2a0c5fecf`，检查前后源码指纹一致。125 项选定后端单元测试、103 项前端测试和 3 项验证器测试通过，Checkstyle 通过。新增 3 项词项测试覆盖原词保留、否定/数字、不把设备编号当订单号，以及不能在空语料上产生证据。

## 保留的失败与下一步

- 补充集“车库在哪层”仍未召回。本轮不读完结果后继续针对该题补词，避免把同一份小数据优化成满分。
- “现在店里剩几个空位”“现在还有几个停车位”会检出静态预约或停车说明。静态说明不能回答实时数量，需要由实时工具提供，缺失时应说明无法确认。
- “电影票交钱以后怎么退”因付款扩展新增误检；补充集虽然误检总数未变，问题构成已经变化，不能宣传为完全没有精度代价。
- 尚未解决逐句引用支持校验。引用编号有效、文档版本有效，不代表“退款条件”等具体结论受到原文支持。下一步应补真实业务知识和人工标注的回答评测，再决定拒答阈值、意图分流或重排方案。
