# UI 与逻辑检查（2026-11-11）

## 已修复

| 问题 | 处理与验证 |
| --- | --- |
| 工程体验页在390/320px手机上溢出，下拉框至少340px，标题被横排按钮挤成窄列 | 下拉框取消最小宽度，卡片操作独立成行，状态和历史记录改成窄屏布局；实际浏览器检查整页宽度 |
| 优惠券手机筛选区过高，禁用按钮仍为橙色，长标题容易挤压 | 分类横向滚动，禁用券使用灰色按钮，标题换行，手机主要操作至少44px高 |
| 订单、个人主页、登录页错误高亮“发现” | 主导航只高亮对应页面，补前端回归 |
| 普通券/秒杀确认方法重复执行可能读取已关闭的弹窗 | 加忙碌与弹窗类型保护，取消订单也做同样处理；测试模拟重复调用 |
| 原列表弹窗直接使用旧价格和规则 | 打开弹窗与明确确认时分别读取精确券预览；价格或规则改变要求再次确认；关闭弹窗或身份变化不继续提交 |
| 新券浏览模块不符合已有Controller依赖服务接口的约束 | 引入 `IVoucherBrowseService`，不放宽原架构测试 |
| 新Mapper使用Map参数，未满足已有声明参数绑定检查 | 改为显式、带 `@Param` 的标量参数；原参数绑定测试通过 |
| 复用Agent预览时只能检查店铺前20张券 | 普通业务页使用 `GET /voucher/preview` 按店铺及券ID精确查询；返回白名单字段与服务端可领取快照 |
| 浏览器时钟或时区可能错误决定限时券按钮状态，缺失类型可能被视作普通券 | 按服务端 `orderable` 快照决定状态，未知类型/缺失状态关闭操作；提交前复核，后端仍是最终交易校验点 |
| 订单翻页在请求期间改变页码，失败后页码可能和旧数据不符 | 请求期间禁止翻页，失败恢复旧页码 |
| 数据变化导致优惠券OFFSET分页前后重叠时出现重复卡片 | 按完整字符串ID去重；这不构成数据库快照分页，仍可能因商品变更出现遗漏 |

同时补充登录重复提交、上传期间重复上传/发布的入口保护；沿用未知提交结果只读核对、不自动重发POST的行为。预览不是原子锁价，不能保证随后库存、资格或价格不再变化。

## 验证结果

- **后端211项通过**：198项独立数据库/缓存回归，13项独立RocketMQ、Kafka、Canal及工程体验集成测试。Checkstyle通过。
- **前端48项通过**：身份、Long ID、请求错误、助手和基础页面的确认/重试/分页等测试。
- Vue 2全站模板编译通过，无警告。
- **隔离无界面Edge：48个页面/视口组合通过**，覆盖1440、1024、390、320px，未发现脚本异常、非预期API错误或整页横向溢出。检查了首页、商户、券、笔记、登录、助手、工程体验和个人/订单/发布页面。
- **6项浏览器交互通过**：真实只读接口的无结果搜索、清空筛选、分类显示和写笔记登录跳转；测试桩的价格变化再次确认、双击只发一次提交。
- **19项本地只读接口断言通过**：搜索、组合筛选、分页、精确预览、无效参数和字面特殊字符等。
- 已更新本地Java运行包；前端为直接挂载。旧包备份位于 `target/ui-audit-before.jar`。

汇总证据：[ui-audit-2026-11-11-verification.json](ui-audit-2026-11-11-verification.json)。浏览器截图与原始报告在 `target/ui-audit-final/`，后端原始报告在该JSON记录的隔离运行目录中。

## 复现页面验收

```powershell
npm.cmd install --prefix target/ui-audit-tools --no-save --no-package-lock playwright-core@1.65.0
node scripts/audit-ui.cjs
```

脚本使用Windows已安装的Edge，启动独立无界面浏览器。个人/订单/发布页面使用测试账号与订单响应，不代表真实账号登录验收；所有真实业务写请求均被拦截，确认流程的POST在浏览器中直接由测试桩回应。没有实际领券、取消订单、付款、发布笔记或调用真实模型。

本轮不是性能压测，也未重跑故障进程强杀系列与缓存性能基准。没有测试真实支付、短信或退款；现有英文baseline券是历史工程测试数据，未修改。通过这些检查不能保证不存在其他缺陷。
