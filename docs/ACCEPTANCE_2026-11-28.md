## 发现并修复的问题

上轮收藏迁移将查询 SQL 放入 Mapper 后，服务直接把返回 Map 内的 `Timestamp` 转成字符串。MyBatis 同一事务内可能复用这个 Map，再次查询时便产生 `String cannot be cast to Timestamp`。真实数据库复现为 3 项中 2 项报错。

现改为创建响应 Map 副本再格式化，不修改 Mapper 持有的对象。新增单元测试让 Mapper 反复返回同一份不可修改 Map，验证重复读取和原始时间类型；数据库原有重复保存/读取用例也已通过。未通过关闭 MyBatis 缓存或放宽断言规避问题。

数据库测试原来直接用 JdbcTemplate 删除笔记，绕过 MyBatis 的事务缓存失效，使同一事务继续读到缓存行。该步骤改用实际业务使用的 BlogMapper 删除，保留“已删除内容必须标记不可用、仍可取消收藏”的原断言。最终通过的三个场景为：重复收藏仍是一条记录且时间/响应格式稳定；不同用户读取及取消互不影响；删除笔记后仍可看到不可用项并取消收藏。

## 复跑方式

仓库根目录执行：

```text
python scripts/run-ci.py
python scripts/verify-favorite-database.py
```

模型质量检查会调用已配置的付费模型，每轮最多 8 个合成样本，连续两条 UNVERIFIED 则停止；凭据来自本机 `.env`，不应提交该文件：

```text
python scripts/verify-answer-support-live.py
```

真实模型评测类 `EvidenceSupportLiveEvaluation` 故意不采用默认 `*Test` 命名，常规 CI 不会自动执行付费请求。真实模型未全部符合标签时命令退出非零，仍保留逐题结果，不将故障降级为通过。

隔离数据库脚本只启动 MySQL、Redis、Memcached；不发布宿主端口，只挂载 pom/src/config 为只读，复制到容器临时工作区执行，报告独立写出。沿用已有测试环境的 SQL 兼容模式，以加载含零日期默认值的课程初始 SQL；不代表已验证生产严格 SQL 模式。测试事务回滚且一次性资源已清理，外部 Maven 缓存保留。

Docker 引擎经正常重启恢复。本次自动化沙箱需要 Docker 管道访问权限；普通环境若报 permission denied，应先区分权限问题和引擎未运行，不据此再次宣称 Docker 故障。
