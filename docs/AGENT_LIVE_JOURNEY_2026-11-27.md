# 小橙真实模型端到端验收

2026-11-27，CityMate 在真实浏览器、真实业务接口和服务端已配置的模型上，完成“找店 → 对比 → 查规则 → 确认领券 → 查询结果”。验收发现并修复了普通券订单状态解释错误；修正后的四个选定问题及 13 项自动检查通过，回答已逐条人工核对。

## 实际链路

| 环节 | 实际结果 |
|---|---|
| 找店与对比 | 查询到三家人均不超过 50 元的演示美食店，商圈、人均与工具数据一致，前端可展开对比；未编造有效评分或定位 |
| 平台 RAG | 回答区分“订单号／受理”“订单生成”和“付款”，引用 `platform-claim-progress` 版本 4，来源原文可按版本查询 |
| 券规则 | 查询桥边小火锅的免费 10 元抵扣券，正确说明满 60 元抵 10 元、每单一张、不叠加；修正后未用无关 FAQ 为券条款背书 |
| 领取确认 | 打开预览不会创建订单；点击确认才发出普通券领取请求，工具和模型本身没有领取权限 |
| 数据库结果 | 首次新增一笔演示免费券订单，状态为 2；复验返回原订单，没有重复创建，不涉及真实收款 |
| 模型核对 | 复验直接调用 `listMyOrders`，按工具给出的状态含义说明“免费券已领取，不涉及真实收款” |

## 发现的问题与修改

首次机械检查通过，但人工阅读最后一条回答发现：模型先对普通券订单调用 `getClaimStatus`，该工具实际上只查秒杀预约进度；失败后又查到本人订单状态 2，却仍说不能确认领取成功。因此首次结果没有按语义验收通过处理。

本次修改：

- `QueryToolViews` 为订单补充 `statusMeaning`，明确免费券领取、待支付、取消和标记完成等状态；未知状态保持待确认。
- 补充 `priceMeaning`，避免把 `payCents` 的券价解释成已经付款或收款的金额。
- 工具定义和系统约束明确：普通券查订单列表，秒杀受理进度才用 `getClaimStatus`；一次不适用的进度查询失败不能推翻已读到的普通券状态。
- 券条款可依据实时券工具的 `rules`；未使用相关知识文档时不引用无关检索结果。

没有增加写工具或更改订单状态、领取规则、支付流程。没有扩大模型的权限、执行步数或超时预算。

- 复验 13 项自动检查通过，四条回答人工复核通过。临时登录会话均已删除。
