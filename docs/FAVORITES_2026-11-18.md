# 收藏与想去清单

日期：2026-11-18。

## 用户怎么使用

1. 在店铺详情点击“收藏店铺”，在笔记详情点击“收藏笔记”；未登录时跳转登录，并保留原页面。
2. 登录后进入个人中心“我的收藏”，查看“想去的店”或“收藏的笔记”。切换标签会更新网址，刷新和从详情返回都保留标签。
3. 点击条目进入详情；不再需要时点击“取消收藏”。不可用内容保留为提示条目，也可以移除。

本轮没有增加真实消费评价、已去状态、消息推送、收藏计数热榜或模型工具。收藏只表示个人保存偏好。

## 后端

- Flyway `V11__user_favorites.sql` 新增 `tb_user_favorite`。唯一键 `(user_id,kind,target_id)`，按用户、类型、收藏时间索引读取。
- `GET /favorites?kind=shop|note&page=1&size=12`：仅本人分页清单，上限 30 条，稳定按收藏时间和主键倒序。
- `GET /favorites/{kind}/{id}`：查询本人收藏状态。
- `PUT /favorites/{kind}/{id}`，请求体 `{"saved":true}` 或 `{"saved":false}`：设置期望状态，而非盲目翻转。
- 用户身份来自服务端登录上下文，不读取客户端 userId。收藏接口由现有 AccessGuard 登录保护；服务层另做防御性检查。
- 写入事务先锁本人用户行，再检查目标和执行唯一键 upsert／删除。重复收藏不会重复记录或改变原收藏时间；重复取消也安全。
- 取消不要求原内容仍存在。列表左连接目标对象，缺失时返回不可用条目，避免产生无法移除的收藏。
- 控制器局部处理主动抛出的 400／401／404，避免被既有全局 RuntimeException 处理吞成通用错误，不修改其他业务错误语义。

收藏直接以 MySQL 为事实来源，没有新增 Redis 副本、消息队列任务或缓存一致性机制。跨设备登录同一账号读取相同记录；并不意味着客户端会实时推送更新。分页不是跨设备变更的快照，可以刷新清单获取最新结果。

## 前端异常处理

- 服务端确认后更新星标，保存期间禁用重复提交。
- 写入超时或响应无法核对时保留原显示，提示重新查询；不自动重试写入，不宣称保存成功。
- 切换用户、类型、内容或销毁组件会使旧请求失效，避免旧账号状态回流。
- 分页失败保留已有记录，重试相同页。确认取消后从第一页重读，避免 offset 随删除移动而漏项。
- 不同用户的清单不存入浏览器本地存储；只在个人主页显示自己的清单。

## 验证与运行

- 前端 103 项单元测试通过，包含重复点击、超时后核对、旧账号迟到响应、分页失败和取消后重读。
- 后端 8 项专项测试通过（服务 5 项、控制器 3 项），包含异常状态映射和客户端伪造 userId。
- Java 格式检查通过，新 JAR 已打包；启动时 Flyway 从版本 10 追加迁移至 11。
- 隔离浏览器 50 组页面／视口、14 项交互通过；测试响应为夹具，没有真实业务写入。截图在 `target/consumer-ui-checks/favorites-390.png` 和 `favorites-1440.png`。
- 实际 MySQL／HTTP 验证脚本：`python scripts/verify-favorites.py`。仅允许使用 `seed-demo-data.py` 的两位保留演示作者，通过临时本地会话测试；不接入短信、真实用户或订单。
- 真实验证结果见 [验收记录](favorites-live-verification.json)，5 组检查通过。脚本验证匿名拒绝、8 次并发幂等、跨用户隔离、类型分离、重复取消和非法参数；结束恢复原收藏标记并删除临时会话，没有创建订单或调用模型。

本轮后端变化需要新 JAR 和 Java 服务重启。前端脚本直接挂载，浏览器用 Ctrl+F5 更新；不需要清空数据库或重新导入旧数据。
