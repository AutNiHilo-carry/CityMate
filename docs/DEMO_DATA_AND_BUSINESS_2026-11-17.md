### 可复用与验证

```powershell
python scripts/seed-demo-data.py          # 只显示计划
python scripts/seed-demo-data.py --apply  # 追加到本地 Docker 库
node scripts/audit-demo-data.cjs          # 实际接口与无头浏览器只读检查
```

脚本固定使用本地 `citymate-mysql-1`，预留 ID 从 880001 起；碰到不同名称的记录会中止。相同 ID 已存在时跳过，不更新；事务提交数据，重复执行不会重置券、笔记或作者。生成静态 SVG 不依赖网络图片。新增数据不是 Flyway 生产迁移，不应默认导入真实运营库。

实测：22 个店铺详情接口通过；全部 10 类门店及券筛选通过，免费／付费券与笔记读取通过，共 12 项业务读取检查；桌面 1440px 与手机 390px 下的找店、券列表、店铺详情共 6 组布局检查通过。重复插入新增记录为 0。

证据：[导入记录](demo-data-verification.json)；浏览器结果和截图在 `target/demo-data-checks/`。浏览器拦截所有非 GET 请求，未登录、未领取、未付款、未调用模型。离屏图片使用原有懒加载策略，不以整页截图中尚未加载的离屏缩略图判断资源丢失。

## 从同类产品借鉴什么

美团 2026 年 7 月公开介绍“小团”按距离、营业状态、评价和余位筛选，确认后再协助预订。对 CityMate 的启发是：自然语言查询应该继续进入可执行、可核对的业务动作，而不是只给一段推荐文案。[官方介绍](https://www.meituan.com/news/NN260727198008607)

大众点评公开介绍评价真实性治理和 AIGC 评价治理，提醒我们把探店内容、平台规则、实时业务事实分开，不能用生成笔记代替真实消费证据。[官方介绍](https://www.meituan.com/news/NN26032719900483X)

以下是针对当前项目的建议，并非上述平台全部功能的逐项复刻：

| 优先级 | 业务改进 | 最小实现与验收 |
|---|---|---|
| P0 | 券的关键限制前置 | 券卡直接显示满减门槛、适用时间、预约要求、适用门店、不可叠加项；详情保留原文。先结构化数据，旧券缺失字段显示“待确认”，不让 AI 推断。确认领取仍复核最新规则。 |
| P0 | 小橙提供候选对比 | 同一问题先给 2～3 家候选，对比人均、商圈、查询到的券和推荐原因；支持“更便宜一点”“只看这个商圈”。后续查询保留显式条件，未知距离／营业状态不编造。复用现有搜索及继续查券能力。 |
| P1 | 收藏与想去清单 | 收藏店铺和笔记，个人页分组“想去／已去”；先做登录用户跨端持久化和幂等收藏。验收重复点击、取消和账号切换。让浏览行为有后续落点。 |
| P1 | 到店前信息与导航 | 地址复制、地图导航链接、营业时段、预约方式。先把营业时段结构化，再做“当前营业”；没有实时余位时不标“可预订”。本轮虚拟门店只展示演示提示，不导航到真实商家。 |
| P1 | 我的券使用指引 | 清楚区分处理中、待支付、已领取、已取消；显示当前可做的下一步。已有真实边界内完善引导，核销与退款在未实现前不可给出假入口或假成功状态。 |
| P2 | 可信内容与运营闭环 | 模拟笔记与真实笔记区分，0 分新店显示“暂无评分”；后续有核销证据再设计“已消费评价”。热榜解释时间窗口和热度来源，并将演示流量与正式统计隔离。 |

建议下一轮先完成“券限制摘要 + 小橙候选对比”，然后做收藏。暂不扩张到外呼订位、真实支付、多城市运营或多 Agent；先把已有“发现 → 比较 → 查规则 → 确认领取 → 查结果”的路径做顺。
