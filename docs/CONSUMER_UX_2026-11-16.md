# 本地生活操作路径与页面优化

日期：2026-11-16。

## 参考依据与改进

参考公开产品资料：[大众点评手机客户端功能介绍](https://events.dianping.com/m/wap.htm)、[大众点评应用介绍](https://apps.apple.com/cn/app/id351091731)、[美团团购服务说明](https://rules-center.meituan.com/m/detail/guize/1)。公开资料围绕商户信息、点评、优惠和消费规则组织功能。本轮结合 CityMate 已有能力作以下设计；未进行原生 App 实机评测，不声称复刻其当前界面。

| 当前操作痛点 | 实现后的行为 |
| --- | --- |
| 顶部搜索固定跳到找店，即使用户正在选券 | 券页搜索优惠券并保留分类、店铺；找店页搜索保留预算和评分；其他页面搜索进入找店 |
| 手机切换订单与个人入口需回到首页或头像入口 | 浏览页底部固定显示发现、找店、优惠券、订单、我的；当前入口有明确高亮 |
| 手机导航占用头部一整行，AI 入口容易与主业务混在一起 | 头部改为品牌 / 账户、搜索 / 问一问两行；底部承载主要页面导航 |
| 店铺照片之后需要继续滚动寻找券和笔记 | 新增店铺信息、优惠券、探店笔记锚点，直接跳到真实内容区 |
| 券的售价与券面金额关系不够直观 | 明确标为券面金额；有有效分值差额时显示“比券面少付”，不将免费、缺失或异常金额编造成折扣 |
| 库存字段缺失时仍显示剩余 0 张 | 缺失数量时不展示虚构库存；是否可领取仍完全依据服务器 orderable 字段 |

登录、发布笔记及工程体验页不显示底部导航。底部留出安全区与内容空间；确认框禁用背景，照片查看器层级高于导航。没有新增支付、券码、核销、定位或订单状态推断。

## 本轮验证

- 前端测试 83 项通过，包含新增的搜索路由、筛选保留、导航范围与金额边界检查。
- 语法检查通过；页面及共享组件 Vue 模板编译 0 警告；修改文件 diff 空白检查通过。
- `node scripts/audit-consumer-ui.cjs`：10 类页面 × 1440 / 1024 / 800 / 390 / 320 像素，共 50 组布局检查通过；新增 8 项交互通过。
- 交互覆盖券页搜索留在当前页、正确差额、直达订单、店铺锚点、确认框背景隔离、大图层级以及首页搜索跳转。
- `node scripts/audit-voucher-state.cjs`：原有 9 项筛选恢复与重试检查通过。
- 已查看桌面券页、手机首页和店铺页截图。本机结果与截图位于 `target/consumer-ui-checks/`，手机可见窗口截图以 `viewport-390` 命名。完整页面截图中的固定导航位于截图拍摄时的屏幕底部，并非文档中间的普通内容块。

浏览器脚本使用随机本地端口的隔离静态页面与 API 夹具，真实业务写入为 0，结束后关闭浏览器和服务。本轮后端代码未改，未重新执行真实后端联调、模型问答或性能测试。手机检查为桌面 Edge 的视口检查，未覆盖原生系统键盘或 iOS Safari。

前端目录由开发服务挂载，启动项目后刷新即可使用，无需重建 Java 包。验证摘要见 `consumer-ui-verification.json`。
