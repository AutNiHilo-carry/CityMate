# 统一启动入口

先打开 Docker Desktop，等待 Engine running。在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-citymate.ps1
```

默认使用 `target/citymate-0.0.1-SNAPSHOT.jar`，启动完整本地环境。没有 JAR，或需要从当前 Java 源码启动时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-citymate.ps1 -FromSource
```

脚本从自身所在位置确定工程目录，检查 Docker 和构建包。存在根目录 `.env` 时显式传给 Compose，使文件中的 AI 配置优先于终端中残留的同名 AI 变量；执行结束后恢复原变量，不显示 Key。

容器启动后，通过实际映射的网页端口检查 `/api/actuator/health` 与 `/api/shop-type/list`，两者均通过才显示访问地址。默认等待 180 秒；需要更久时可追加 `-ReadyTimeoutSeconds 300`。超时会显示容器状态及查询日志的命令，不会删卷，也不直接宣称启动成功。

本次验证：PowerShell 语法检查通过；一次 30 秒短等待触发了预期的未就绪报告，随后使用默认等待时间成功通过实际代理健康检查与分类查询。Java 初始化曾超过 30 秒，未将其统计为启动耗时基准。现有 Nginx 动态解析配置保持不变。

默认入口不会重新编译 Java；修改 Java 后需要重新构建包或使用 `-FromSource`。本次未额外调用模型或新增业务功能。
